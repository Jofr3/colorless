| D12 | P2-M1 catalog surface & legality source of truth | `GET /cards` gains **repeatable `id`** (≤100, deck hydration in ONE call; chunked IN + in-memory ordering twin of the SQL sort), **`nameExact`** (case-insensitive whole-name equality), `serie`, `illustrator`, `text` (LIKE over ability/attack JSON), plus the kind params above; **`GET /facets`** serves the filter vocabularies (7 DISTINCTs, one db.batch, KV-cached). `CardBrief` += **`legal {standard,expanded}`**; KV namespace → **`catalog:v3:`**, with KV **bypassed** for >512-byte keys and any `?id=` request (per-deck id sets never recur — caching them is pure write waste). Web: **`Format.legalFlag`** keys BOTH the `legalOnly` filter (`legal=<flag>`) and `isLegalInFormat` (structured verdict beats printed mark; mark check only for legal-less fixtures) — one legality definition for grid + validator. Deck rules: **Radiant = 1 per deck total** (like ACE SPEC; official rule), Prism Star = 1 per name. *Why: filters needed server truth for correct totals; hydration was an N-request fan-out; legality had two disagreeing definitions.* (2026-07-14) |
| D13 | Manual-order persistence model (P2 task 17) | `position` INTEGER on `decks` and `folders` — **global per user, not per folder**: the web grid's flat array (position-ascending) IS the manual order, per-view filtering preserves relative order, and a nest move keeps the row's slot (folderId changes, position doesn't) — exactly the client's existing semantics. Creates take **min−1** (new rows prepend); migration 0003 backfills existing rows in the old name-order so nothing visibly moves. A reorder permutes the in-view rows **among their own slots' position values** (`applyReorder` returns the rewritten array + the changed `{id, position}` pairs) and persists via **`POST /decks/reorder` / `/folders/reorder`** — absolute assignments, ≤500 rows, applied atomically in one db.batch; unknown/foreign ids → 400 naming them; failure recovery is **resync**, not per-row rollback (the folder-delete precedent). Reorder deliberately does NOT bump `updated`. *Why: slot-permutation keeps payloads at the size of the move (not the scope), needs no renumbering pass ever, and one atomic endpoint beats N racing PATCHes.* (2026-07-14) |

| D14 | Engine core contract (P3-M1) | **`applyAction(state, action) → {ok:true, state, events} | {ok:false, error}`** — one reducer, never throws, never mutates. `GameState` is plain JSON (the mulberry32 `rngState` lives **inside** it, so same seed + same actions replay identically); card instances are **uids** (`"p1#0"`) over an injected `cardPool` carried in the state (keeps `applyAction` a pure 2-arg pair and snapshots self-contained). Seats **`p1`/`p2` are labels, not turn order** — the coin winner *chooses* first via an action, `firstPlayer` records it. **Choices are actions; mandatory steps auto-resolve** inside the reducer (mulligan redraws, prize setting, the turn-start draw), so a `Phase` exists only where a player owes a decision. **Events are the animation + wire contract** (semantic, serializable, payloads always copied — never aliasing state or the caller's action). **Wire-safety:** TS types are not input validation — P4 decodes actions from clients, so every index/seat/count an action carries is runtime-checked (three real card-destroying bugs came from exactly this: a JSON string `"1"` bench index). *Why: the engine runs in two runtimes (web local play + the authoritative DO), and an authoritative server needs a total, replayable, non-throwing function of (state, action).* (2026-07-14) |
| D15 | Mulligan compensation (rules correction) | Each player may draw 1 card **per opponent mulligan**, and **mulliganing yourself does not forfeit it** — so **both** seats can be owed at once (each off the other's count). `reference/ptcg-rules.md` §3.5 previously read "the non-mulliganing player", which the M1 engine implemented as an exemption that does not exist; the reference doc is corrected and the phase now carries a per-seat `owed`/`decided` map. The compensation draw is **clamped** so a player can never draw below the 6 cards they must still set aside as prizes. *Why: a wrong rule in the spec propagated straight into the engine — the reference doc is the source of truth and had to be fixed at the source.* (2026-07-14) |
| D16 | M2 staged turn tail, KO interrupts & damage modifiers (P3-M2) | The turn tail is a **`pending: PendingStage[]` queue** on `GameState`, drained by `advance()` (flow.ts): automatic stages run, decision stages either **park** (phase becomes the matching `ko:takePrizes`/`ko:promote` interrupt, prompt event emitted) or **auto-resolve** when only one legal resolution exists. `attack` seeds `takePrizes`+`promote` ahead of the shared `turnTail(seat)` triple. The parked phase mirrors `pending[0]` (dual encoding, kept deliberately for M2): handlers cross-check the two and reject with **`PHASE_DESYNC`** on mismatch. Win evaluation lives in ONE place — the shared `resolvePrizesAndResume`/`resolvePromotionAndResume` helpers used by both the action handlers and advance's auto-resolves. `gameOver` carries **`GameOutcome`** (`win {winner, reason}` \| `tie {reasons}`); sudden death is surfaced as `tie`, not played out. Printed weakness/resistance parse to a **`DamageModifier {op: multiply\|add\|subtract, amount}`** (×N / +N / −N; unknown garble keeps modern-era ×2/−30 defaults) applied weakness→resistance, floor 0 (§8.5); `DAMAGE_DEALT` carries the modifiers so animators can show the math. Data gaps never guess a KO: `hp ≤ 0` reads as the null data gap. *Why: KO resolution must pause mid-tail for player choices, M3's checkup KOs reuse the same interrupts, and additive legacy weakness ("+20", schema-documented) was being silently misread as ×2.* (2026-07-16) |
| D17 | Engine→playmat projection contract (P3) | **`projectGameState(state, viewerSeat) → GameProjection`** (`src/features/game/projection.ts`): `{ board, piles, pokemon, turn, activePlayer, waitingOn, pendingDecision, outcome }` — `board` is a drop-in playmat `BoardState` (`you` = viewer); the wrapper carries what BoardState can't (`piles` deckCount/discard, `pokemon` = per-uid `{damage, hp}`, `outcome` per-viewer win/tie). **`activePlayer` = turn owner; `waitingOn` = the seat that must act NOW** — the split exists because during `ko:promote` the actor is the NON-turn player (the KO'd defender), and a UI gating on turn ownership alone soft-locks. Hidden info is redacted structurally: opponent hand = positional backs (`opponent-hand-N`, no uids — a uid is stable across zones and would let a client track a hidden card), both prize piles = counts only, decks = counts. Public cards key off the engine **uid** so the Pixi layer animates a card as one object across projections. The phase mapping is an **exhaustive switch** (`satisfies never`) — a new engine phase is a compile error, not a silent guess. *Why: this is the same per-viewer filter P4's server will apply; building it client-side first pins the contract with tests.* (2026-07-16) **Revised 2026-07-17 (wire-up review):** during any `setup:*` phase the OPPONENT's active/bench also project as face-down backs (positional `-hidden` ids, no `pokemon` rows — a row would leak the uid key + printed HP); a hot-seat viewer flip at Ready was exposing the first player's face-down placements. Reveal re-keys positional→uid (remount, not flip) — the same trade as hand backs. |

| D18 | Local play page & engine card-pool sourcing (P3 wire-up) | **`/play`** is a hot-seat local match: `GamePage` owns `GameState` via `useLocalGame` (pure reducer over `applyAction`), renders `projectGameState` through the extracted presentational **`PlaymatView`** (the `/simulator` mock, retitled "Sandbox", is a thin wrapper driver), and the **viewer follows `waitingOn`** for the device flip. The engine `cardPool` is built client-side by **fanning out `GET /cards/:id`** (`src/features/game/cardPool.ts`, concurrency 8, module-level promise cache; 404s cache as stable `missing`, rejections self-evict) — NOT via the brief-returning batch route. *Why: `CardBrief` deliberately omits the combat blobs (attacks/weakness/retreat) the engine reads; the per-id route already serves the full canonical Card KV-cached, and this needed no api change while api deploys stay user-gated. A `?full` batch param is the logged follow-up to bundle with the next deploy.* (2026-07-17) |
| D19 | Drop-legality is a driver-supplied predicate (P3 wire-up review) | `AnimatedCardsLayer` takes an optional **`PlacementPredicate`** (defaults to the sandbox's `canPlace`, so the mock is untouched); `/play` supplies `gamePlacementPredicate(game, viewerSeat)` — a deliberately **coarse, gesture-class** gate (phase-aware: what CAN ever map to an action) kept in lockstep with `moveToAction` by a property test (every afforded drop translates to a non-null action). Fine-grained legality stays with `applyAction` + the error pill. Hand→hand reorder is rejected on /play (the engine owns hand order; affording it was a silent lie). *Why: the phase-unaware mock `canPlace` afforded gestures the engine could never accept (accept-animation → wrong-rule error pill), and M4 evolve/trainer drags can't be expressed through it — the seam had to move to the driver.* (2026-07-17) |
| D20 | Text-derived attack effects (P3-M3) | Status-applying attacks resolve through a **conservative exact-sentence deriver** (`packages/engine/src/effects.ts`): five anchored whole-effect patterns ("Your opponent's Active Pokémon is now {X}.", the coin-flip-gated variant, "This Pokémon is now {X}.", the Rest heal compound, the raised-poison Checkup variant) compile to a tiny **`EffectStep[]`** program (applyStatus/heal/coinFlipGate) executed after damage, before the KO check; ANY other text keeps today's loud `ATTACK_EFFECT_SKIPPED`. This is the first sliver of D8's op-program system — M4's id-keyed registry will sit ABOVE it (`programFor(cardId) ?? derive(text)`), and the interpreter is deliberately still attack-private until M4's ops force its real shape. **Self-`Paralyzed` is excluded from the self-pattern**: official wording clears paralysis only if "Paralyzed since the beginning of your last turn", so self-paralysis at your own turn's end must SURVIVE the immediate checkup — our blanket ended-seat clear (correct for every opponent-inflicted case) would wrongly erase it, so the deriver refuses the sentence until paralysis carries an applied-turn stamp; `reference/ptcg-rules.md` §12/§13.4 corrected at the source (the D15 precedent). Demo decks swapped in real status attackers (Numel sv03-031 ×3 Fire/Burn, Luvdisc sv02-047 ×3 Water/Asleep) so /play exercises the pipeline. *Why: statuses without an application path are dead code until M4; exact-sentence matching makes dozens of real cards fully simulated with zero guessing, and the apostrophe class (`['’]`) is the only tolerance so a re-ingest can't silently un-derive them.* (2026-07-17) |
| D21 | Battle state rides the CardModel (P3-M3 surface) | `CardModel` gains **`battle?: {damage, hp, conditions}`**, attached by the projection to in-play Pokémon only — the `statuses` side-table (`GameProjection.pokemon`, prop-drilled 5 hops to DamageChip) is DELETED; chips (damage + the new SLP/PAR/CNF/BRN/PSN pills) read the card they decorate. The playmat stays engine-free: `BattleConditions` is a structural restatement of the engine's `SpecialConditions`, pinned by a **two-way compile-time assignability assert** in `battleStateOf` (an added engine condition field fails the build instead of silently never rendering); `conditions` is REQUIRED (`NO_CONDITIONS` const for mocks) so a missing object can't read as "no conditions" downstream. The checkup itself runs entirely inside `advance` — **no new Phase members**; its KOs park on the existing ko:* interrupts, and the projection reports **`activeSeat: null` for between-turns parks** (discriminated by the pending queue: an in-turn KO still carries its endTurn/checkup tail, a checkup KO has drained it to bare startTurn). *Why: the side-table was the wire-up review's known wart; co-location kills the drilling, and the vocabulary stays out of the playmat per the zero-engine-imports rule — lift it to `@luminous/schema` when M4 markers force the shape to grow.* (2026-07-17) |

| D23 | Trainers + Abilities via a resumable effect interpreter (P3-M4 slice 2) | The real first appearance of D8's op-program system (D20's deriver was "the first sliver"). **One shared interpreter** (`packages/engine/src/interpreter.ts`) runs every op program — attacks, Trainers, Abilities alike; the M3 attack-private `runEffectSteps` is GONE. Attacks resolve `programFor(id)?.attack ?? deriveAttackEffect(text)` at the one call site (registry ABOVE the deriver, `registry.ts`); Trainers/Abilities have NO text deriver — an unauthored one loudly can't be played/used rather than guessing. **Mid-effect decisions PARK** via a new `effect:choose` Phase carrying a JSON continuation (`{pendingOp, rest, ctx}`) — replayable, and OUTSIDE the KO/win tail (no in-scope effect KOs or ends the game, so the interpreter never touches flow.ts). New actions: `playTrainer` (Item unbounded §7.1 / Supporter 1/turn §7.2 + the §4 first-turn Supporter ban; the card discards up front — none references itself mid-effect), `useAbility` (activated only; the once-per-turn per-Pokémon flag lives in `TurnAllowances.abilitiesUsed`, §9/§15.J), `resolveEffect` (the parked-decision resolver, every choice wire-checked against the prompt — the D14 never-throw contract extended to the effect layer). New ops: drawCards / discardHand / shuffleDeck / searchDeck→(bench|hand) / switchActive / gust / healChosen (+ M3's applyStatus/heal/coinFlipGate unified into `EffectOp`). **Passive abilities are a pipeline HOOK, not the interpreter** (Bouffalant "Bouffer": −20 damage AFTER Weakness/Resistance, read at the attack damage step; `DAMAGE_DEALT` gained an optional `reduction`). **Web:** Trainers/Abilities are HUD **buttons** (not board drags — the drag layer already no-ops on unknown phases, so `effect:choose` affords nothing), and `effect:choose` renders a chooseCards / choosePokemon dialog; §4/§7.2/§9 gating is mirrored on the buttons but the ENGINE owns fine legality (gust/switch with no legal target reject → the D19 pill). Representative set only — 6 Trainers (Professor's Research / Nest Ball / Boss's Orders / Switch / Potion / Energy Search) + 2 Abilities (Chien-Pao ex *Shivery Chill* activated, Bouffalant *Bouffer* passive), real sv01–sv03 ids in the demo decks; **broad SV-pool coverage is a later Workflow fan-out that just adds registry rows.** engineVersion 0.5.0. *Why: the M3 traps predicted exactly this — the registry sits above the deriver, and the interpreter had to be RESTRUCTURED (not extracted) to gain mid-effect parking + non-Active targets. Doing Trainers AND Abilities together proved the one interpreter serves both trigger models (play-a-card vs use-an-ability) and the passive-hook path, so the shape is validated before scale.* (2026-07-17) |
| D24 | Persistent-zone Trainers via a continuous-modifier pipeline (P3-M4 slice 3) | Stadiums (§7.3) and Pokémon Tools (§7.4) don't run op **programs** — their effects are **continuous**, so a new module **`packages/engine/src/continuous.ts`** aggregates them and is the ONE place a rule read consults them: `effectiveRetreatCost` (turn.ts retreat), `effectiveAttackCost` (attack.ts cost check), `effectiveMaxHp` (flow.ts `isLethallyDamaged` — the KO test — and the web `battle.hp`), and `passivesOf` (attack.ts damage: a defender's post-W/R reduction — now Bouffalant "Bouffer" **and** a defending Tool — plus an attacker's pre-W/R bonus). **Stadium** is a single shared **`GameState.stadium` {uid, owner}**: `playTrainer` routes Stadiums to `playStadium` (one/turn via a new `stadiumPlayed` allowance; replace-on-play discards the predecessor to **its owner's** pile; the same-**NAME** ban compares names not ids, so the sv02-171/sv03-229 "Artazon" reprints can't self-replace); allowed on turn 1 (§4 bans only Supporters + attacking). **Tool** is a new action **`attachTool`** (NOT playTrainer — it carries a target): one per Pokémon, uncapped per turn, no allowance consumed, no detach — it rides the stack through evolution and discards with a KO'd stack (the `tools` slot M1 reserved is finally populated). Both a Stadium and a Tool with NO authored `stadium`/`passive` row reject loudly (`TRAINER_NOT_SIMULATED`) — the coverage strategy, not a silent no-op. Representative set: Beach Court (sv01-167, Basic retreat −1) + Pokémon League HQ (sv03-192, Basic attacks +{C}) + Vitality Band (sv01-197, +10 before W/R) + Bravery Charm (sv02-173, Basic +50 HP). **Web:** Stadiums are BOTH a HUD button and a drag onto the shared stadium slot (`moveToAction`/`gamePlacementPredicate` gained the `owner:"global" zone:"stadium"` exception — the one non-own drop target); Tools attach by drag onto an own Pokémon (the energy-attach gesture). The projection shows the shared Stadium public (it can't exist during setup) and `battle.hp` reads the continuous max HP; HUD retreat/attack costs read the effective ones. engineVersion 0.6.0. **Deferred gap (documented, not silent):** evolution can now LOWER effective max HP (a Bravery Charm's Basic-only +50 dropping off), so a damaged charmed Basic that evolves below the new stage's HP should KO the instant it evolves (§8.1) — but `evolve` runs no KO check and the engine's KO flow is Active-only + turn-ending. An Active in that state is cleaned up at the next Checkup; a benched one is not (the same Active-only KO limit bench spread damage already carries). A mid-turn KO that RESUMES the actor's turn is new flow machinery, deferred with the bench-KO generalization; pinned by a characterization test. *Why: Stadium/Tool effects are continuous reads, not the interpreter's mid-effect programs, so a pipeline module — not registry op arrays — is the right seam, and it unifies the passive hook D23 introduced (Tools and printed passives feed one read site).* (2026-07-18) |
| D25 | Knock Out generalized off the Active (P3-M4 slice 4) | The KO flow was **Active-only + turn-ending**; two reaches needed it generalized. (1) **`knockOut(state, koedSeat, koedUid, prizeSeat, events)`** now KOs ANY in-play Pokémon, found by its stack-top **uid** (so a batch of KOs can't shift a later target's bench slot): a benched KO discards the whole stack, compacts the bench, and seeds ONLY a `takePrizes` stage — no promotion, since it leaves no empty Active spot. (2) **`collectKnockOuts(state, seats, events)`** is the ONE post-damage sweep — every lethally-damaged in-play Pokémon (Active + Bench), prizes to each KO'd side's opponent (`otherSeat`, universal per §8.1), stages grouped **prizes-first**, and the §14 **tie guard runs only when both seats lost a Pokémon** (a one-sided batch only ever wins for the one player) via the same speculative `evaluateWin`. It replaces the inline KO blocks in `attack.ts finishAttack` (now sweeps the defender's WHOLE board — the Active from base damage AND any sniped Bench) and `flow.ts runCheckup`, so §14 precedence stays single-sourced. (3) **A new `PendingStage {kind:"resumeTurn"; seat}` + `resolveMidTurnKnockOuts`**: a KO mid-turn (not from an attack) resolves its prize/promote stages then **RESUMES** the actor's turn (phase back to `turn:action`) instead of ending it — allowances live on `GameState`, untouched by the interrupt. This closes D24's **deferred evolve-below-HP gap**: `evolve` now runs the KO check, so a benched charmed Basic that evolves below the new stage's HP (a Bravery Charm's Basic-only +50 dropping off — the one effect that LOWERS effective max HP) is Knocked Out the instant it evolves, mid-turn, with the opponent taking the prize on the actor's turn. (4) **A `spreadDamage` op** (`{op:"spreadDamage", target:"opponentBench", amount}`) placed by the interpreter — flat damage to EACH opponent Benched Pokémon (no Weakness/Resistance on the Bench, §8.5); the interpreter only PLACES it (one `DAMAGE_DEALT` per benched Pokémon), the KO check staying in `finishAttack`, so the interpreter still never KOs or touches the flow tail. A sixth deriver sentence recognizes "This attack does N damage to each of your opponent's Benched Pokémon." (optional W/R clarifier). **Web:** the ONLY source change is `projection.ts koParkActiveSeat` treating `resumeTurn` as in-turn (a mid-turn KO park still reports the actor as `activePlayer`); the exhaustive `phaseViewOf` Phase switch is untouched (`resumeTurn` is a PendingStage, not a Phase), and the log/HUD need nothing — `DAMAGE_DEALT`/`KNOCKED_OUT` resolve a benched uid the same way, and the opponent's mid-turn prize pick rides the existing `waitingOn` viewer-follow. Representative demonstrator is a fixture spread attacker (Spread Shot); a live sv card lands with the coverage fan-out. engineVersion 0.7.0. *Why: bench spread/snipe damage (a large card class) and the evolve-below-HP correctness gap both needed the KO target generalized AND a mid-turn KO that resumes the turn — one sweep serving the attack, checkup and mid-turn paths keeps §14 single-sourced, and keeping the KO check out of the interpreter preserves the D23 rule that flow.ts owns every Knock Out.* (2026-07-18) |

| D80 | Half-open sockets are swept with the runtime's OWN keepalive timestamp (P4 online, increment 3c-viii) | The gap 3c-v's browser run surfaced, and the last known way an online match could stall. `setWebSocketAutoResponse` answers the client's 1.5s ping without waking the DO — the thing that makes hibernation worth having — but it also means the DO can never notice pings that STOP. A network that dies without a TCP close therefore left a socket that looked perfectly live forever: `hasSocket` said yes, no disconnect grace was armed, no forfeit clock started, and the opponent waited indefinitely. Every ORDINARY exit (tab close, browser kill, navigation, reload, crash) delivers a close event, which is why this never bit in practice and why it took a deliberate `set offline` to reproduce. **The fix is to read the signal the runtime was already recording:** `state.getWebSocketAutoResponseTimestamp(ws)` returns when it last auto-answered that socket, so liveness costs nothing at ping time. The alternative — dropping the auto-response and stamping `lastSeen` in `webSocketMessage` — was rejected on exactly that ground: it would wake the DO ~40 times a minute per socket and give up hibernation to learn what the runtime already knows. **What it costs instead is a POLL**, because a quiet in-game lobby schedules no alarm at all: `scheduleMaintenance` now pushes a `LIVENESS_SWEEP_MS` (30s) deadline whenever any socket is connected, so an occupied lobby wakes twice a minute. `SOCKET_SILENCE_MS` is 15s — ten missed pings, so a phone changing networks or a throttled background tab is not mistaken for a dead one — and a test pins the budget that matters: sweep + silence + the 5s grace all fit inside the 90s forfeit, so a dead network can never resolve slower than a closed tab. **A `null` timestamp counts as ALIVE**, deliberately: it is the state of every connection before its first ping, and nothing can distinguish "just opened" from "opened long ago and never pinged" — the cost of that reading is a socket we never sweep, versus closing a healthy one-second-old connection. **The sweep only CLOSES**; everything after it — the grace, the seat going disconnected, the forfeit — is the machinery a real close already drives, reached through the same `socketGone` (called explicitly, since a server-side `close()` delivers no `webSocketClose` event to us). 1874 → **1878** tests. **BROWSER-VERIFIED with the very reproducer that exposed the bug:** with a match live, one client was put offline with the socket left open; before this change that produced nothing at all, and now the opponent saw "disconnected — forfeits in 1:30" after ~50s (15s silence + up to 30s sweep + the 5s grace) and the countdown ran. Zero page errors. *Why: the cheapest signal is the one someone else is already recording. ## Locked assumptions (override explicitly if they change)
- Bun-workspace monorepo; API + Lobby DO on Cloudflare **Workers** via `wrangler`.
- **Hono** + **Zod**; **Drizzle** over D1. Ingest uses **plain REST fetch +
  our Zod schemas** — the official `@tcgdex/sdk` turned out unnecessary since
  we validate every payload ourselves anyway (changed 2026-07-09, was: SDK).

  child tables only if we need to query inside them).

- The **match engine (P3)** is the actual gameplay; approximate at first,
  improved iteratively.

## These are defaults, not law
Every decision and assumption here is a **default with a rationale**, chosen with
the context available at the time — revisit any of them when the code or new
context reveals a better path. The point of writing them down is to preserve the
*why*, so a later session can judge whether it still holds.

## Adding / changing a decision
Append a row (or a dated subsection for bigger ones) with the choice **and the
one-line why**. When you revise an existing decision, update its row and note
what changed and why. The one hard rule: **don't reverse a decision silently** —
leave a trail so the reasoning is never lost.
